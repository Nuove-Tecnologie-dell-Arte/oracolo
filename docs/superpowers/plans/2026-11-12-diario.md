# Diario di bordo nella Nebulosa — piano di implementazione

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** i pensieri del Diario di bordo entrano nella nebulosa come nuova categoria `diario`, con filtro DIARIO nell'header e il gruppo di chi scrive sotto ogni pensiero.

**Architecture:** un modulo `backend/diario.py` legge l'API pubblica del diario e scrive nel DB SQLite locale con una fascia di id propria e una nuova colonna `gruppo`; `sync` scarica stampante e diario in modo indipendente; server e frontend fanno viaggiare `group` accanto a `source` e lo mostrano come firma.

**Tech Stack:** Python 3.12 (stdlib `http.server`, `requests`, `sqlite3`, pytest), React + TypeScript + Vite.

**Spec:** `docs/superpowers/specs/2026-11-12-diario-design.md`

## Global Constraints

- Commenti, docstring, log e testi del frontend in italiano.
- Backend senza framework web; import sempre `backend.<modulo>`, mai `src.*`.
- `DIARIO_ID_BASE = 2_000_000_000`; id entry = `DIARIO_ID_BASE + id del diario`.
- Categoria `'diario'`; colonna `entries.gruppo TEXT` (NULL fuori dal diario), con il nome leggibile da `/api/categorie`, o la chiave se sconosciuta.
- Il gruppo non va mai in `source` (che significa "citazione da un testo" ed è letto da `themes.py`): viaggia come `group`.
- `DIARIO_API_URL` default `https://diario.nuovetecnologiedellarte.it`; vuoto = diario disattivato. Pagine da 100. Timeout `REMOTE_API_TIMEOUT_SECONDS`.
- Pulizia dei pensieri spariti solo dopo uno scaricamento completo riuscito.
- Nessun `git push`. Commit solo dei file del task (`git commit -- <file>`): nel working tree ci sono modifiche non committate di un altro lavoro (SearchBar.tsx, TagDetailPanel.tsx, index.css, TagDetailModal.tsx eliminato) che non vanno incluse. Nei task che toccano TagDetailPanel.tsx e index.css usare `git add -p` e mettere in stage solo i pezzi del diario.

## Review Focus

- Diario che risponde con errore a metà paginazione → nessuna scrittura, nessuna pulizia (test in Task 2).
- Diario che risponde con zero pensieri a un `sync` riuscito → la pulizia toglie tutte le entry diario: è il comportamento voluto (diario svuotato), ma solo con risposta valida con `totale: 0` (test in Task 2).
- `REMOTE_API_URL` vuoto (situazione di oggi) → `sync` non deve fallire per la stampante se il diario va (test in Task 3).
- DB creato prima di questo lavoro (senza colonna `gruppo`) → `init_db` la aggiunge e le query non si rompono (test in Task 1).
- Cinque filtri nell'header su schermo da 375px → nessuno scroll orizzontale né testo tagliato (verifica visiva in Task 5).
